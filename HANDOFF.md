## Sequence 4 — completed
- Migration `0002_run_status_enum`: adds native Postgres enum `coding_run_status` (`DRAFT`/`REVIEWED`/`APPLIED`), replacing `CodingRun.status`'s Sequence-2 placeholder `String(32)`. Existing rows are uppercased before the `ALTER COLUMN ... USING status::coding_run_status` cast (mirrors how `coding_run_kind` already stores Python enum *names*, not values). `downgrade()` casts back to string and explicitly drops the enum type — same up→down→up regression `tests/db/test_migrations.py` already covers generically, no new test needed.
- `POST /api/questions/{id}/runs` `{kind: "ai"|"import", target_codes?, cluster_overrides?, codebook_source?, enrich?}`: resolves the question's most-recently-preprocessed `Dataset` (409 if none), creates a `DRAFT` `CodingRun`, and enqueues `app/jobs/codebook.py::run_create_codebook_job`.
  - `kind="ai"`: `codeframe.clustering.embed` → `discover_themes` → `codebook.generate_codebook` (notebook S2) against the dataset's valid `Response.translated_text` rows.
  - `kind="import"`: `codebook.load_user_codebook` from a `codebook_source` that's either a bare list/dict-list, `{"rows": [...]}`, or `{"format": "xlsx"|"csv"|"json"|"txt", "content_base64": ..., name_column?, id_column?, definition_column?, sheet?}` (decoded to a tempfile, mirrors Sequence 3's MinIO-bytes-to-tempfile pattern). Optional `enrich: true` runs `codebook.enrich_with_ai` on blank definitions.
  - Either way, every code (including any catch-all `generate_codebook` already added) gets a stable `code_id` (auto-slugified if missing) and `status: "proposed"` before being saved to `CodingRun.codebook_json` — **all codes go through the same review gate regardless of source**, a deliberate simplification vs. the Playbook's wording (which could be read as import-codes-skip-review).
- Review endpoints (`app/routers/coding.py`), only while `status == DRAFT`:
  - `PATCH /api/runs/{id}/codes/{code_id}` — accept/reject/edit name+definition. Mutates `codebook_json` in place, so every handler calls `sqlalchemy.orm.attributes.flag_modified(run, "codebook_json")` before commit (JSONB in-place mutations aren't auto-tracked).
  - `POST /api/runs/{id}/codes` — manual add, `status: "accepted"` immediately (a human just typed it, no AI review loop needed).
  - `POST /api/runs/{id}/finalize` — 409 if any code is still `"proposed"`; if no accepted code matches the project's catch-all name, auto-injects one via `codebook.ensure_other_code` (reusing its real bilingual metadata generation, not reimplemented) and marks it accepted. Flips `DRAFT → REVIEWED`.
- `POST /api/runs/{id}/apply` — 409 unless `REVIEWED` **or** already `APPLIED` (re-apply is allowed and safe — see idempotency below). Enqueues `app/jobs/apply.py::run_apply_job`: builds a `Codebook` from *accepted* codes only, runs `codeframe.coding.apply_codes` against the run's dataset, writes one `CodeAssignment` row per assigned code (mapped by code name → stable `code_id`), aggregates `usage_log` into `CodingRun.token_usage`, flips to `APPLIED`.
  - **Idempotency built in from the start** (not found-then-fixed like Sequence 3): `run_apply_job` deletes existing `CodeAssignment` rows for the run before inserting, and the router's status gate explicitly allows `APPLIED` as a valid re-entry state. `tests/coding/test_apply_job.py::test_reapplying_is_idempotent` and the manual flow's re-apply step both assert `total_coded` is unchanged (not doubled) — this is the exact bug class Sequence 3 hit, caught proactively this time.
- `GET /api/runs/{id}/qa` — 409 unless `APPLIED`. `app/qa.py::compute_qa_metrics` is a **pure function** (plain dicts, no ORM) computing uncoded rate, catch-all rate, multi-label histogram, low-confidence samples (<65% — matches the prototype's QA Review copy), near-zero-frequency codes (<2%, catch-all excluded), and top co-occurring code pairs. Directly unit-tested against hand-built fixtures (known catch-all rate = 2/25, near-zero rate assertions) in `tests/coding/test_qa.py`, independent of the DB/API wiring.
- `tests/coding/` (24 tests): `test_codebook_ai.py`, `test_codebook_import.py` (list/json/csv/xlsx sources + missing-ID auto-generation), `test_review.py` (accept/reject/edit/manual-add/finalize gates), `test_apply_job.py` (coverage + rejected-codes-never-assigned + idempotency), `test_qa.py` (pure-function fixture + API wiring). `conftest.py` adds a `seed_dataset`/`seed_tiny_survey_dataset` fixture that inserts `Response` rows directly via `SessionLocal()`, bypassing upload/preprocess entirely (already covered by Sequence 3) so coding-stage tests get fully deterministic input text for the fake LLM's keyword-based matching.

- One implementation bug found and fixed **before** it reached tests: `finalize_run`'s catch-all injection first built a scratch `Codebook` containing placeholder `Code(code_id=..., name="")` entries to reuse `codebook.ensure_other_code`'s metadata generation — but any code having a non-empty `code_id` makes `Codebook.has_code_ids() == True`, and `ensure_other_code` refuses to auto-inject into a codebook that `requires_manual_ids()` without an explicit `other_code_id`. Fixed by generating the catch-all's `code_id` first (via the existing `_next_code_id` helper) and passing it explicitly to `ensure_other_code(..., other_code_id=new_id)` against an *empty* scratch codebook, instead of one pre-seeded with ID-bearing placeholders.

## Note for next session
- `make.exe` is still blocked on this Windows host by an Application Control policy — use raw `docker compose` commands locally.
- **Always run `docker compose build` (all services, no service arg) after backend code changes** — `api` and `worker` are separate images from the same Dockerfile and silently drift apart otherwise. Bit us again this session (had to rebuild twice after the finalize() catch-all fix) — this is now a recurring lesson, not a one-off.
- **Always run `docker compose run --rm api ruff check .` AND `bash scripts/check_org_scoping.sh` locally before opening a PR**, in addition to `pytest`.
- This host has an unrelated stray Python process bound to `127.0.0.1:8000` (PID varies; `Get-NetTCPConnection -LocalPort 8000` shows it alongside Docker's own forwarder) from a different, unrelated project (`codeframe-webapp`) — it intercepts plain `curl http://localhost:8000/...` on this machine. Don't kill it without asking; instead run manual flows via `docker run --rm --network codebench_default ...` hitting `http://api:8000` (Docker service DNS), as this session did (see `manual_coding_flow.sh` invocation above).
- When building a job that mutates a JSONB column in place (not full reassignment), remember `sqlalchemy.orm.attributes.flag_modified(obj, "column_name")` — a plain `run.codebook_json["codes"][0]["status"] = "x"` without it silently fails to persist.
- Idempotency (delete-then-insert before writing job output) is now a standing requirement for every job that writes DB rows, not just something to catch after the fact — Sequence 4's apply job built it in from the start and the manual flow explicitly re-applies to prove it.
